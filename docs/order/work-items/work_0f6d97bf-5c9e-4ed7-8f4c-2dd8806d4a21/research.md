This ledger is the factual bridge that the previous G-F09 package lacked. It is not a technical design. For each manifest-canonical stable P3 requirement it records the exact canonical required behavior, the factual R1 realization evidence, the current realization verdict and any owned finding/dependency. A downstream `POSITIVE_NO_CHANGE` is admissible only when it points back to a row whose evidence actually proves the complete relevant behavior.

Verdict meanings:

- `CONFORMS` — current realization evidence satisfies the stable requirement.
- `CONFORMS_WITH_DEPENDENCY` — the requirement's own realization conforms, but an explicitly owned upstream/cross-cutting correction must remain visible to downstream design.
- `CONFORMS_WITH_VERIFICATION_GAP` — behavior conforms but permanent certification for the full obligation is incomplete.
- `MIXED` — the requirement has conforming sub-obligations and one or more exact violated sub-obligations.
- `VIOLATES` — the direct realization fails the requirement.
- `VERIFICATION_GAP` — the requirement itself is permanent certification and the required proof is incomplete.
