# Implementation plan — lifecycle documentation authority drift

## Root-cause remediation tasks/dependencies

1. Amend P3/P1/P6 canonical owners with stable GW-FR-096/097/098 and independent review semantics; retain the released V1 semantic sources byte-identically and advance the amended live owners to V2.
2. Extend the single WorkItem schema catalog with immutable historical v1 pins and current Change/Defect v2 pins.
3. Add authority-aware v2 R2/DESIGN/PLAN/R3 templates and structural validation at the schema owner.
4. Restore pure functional-core stage conformance output admission.
5. Wire coordinator stage promotion through that admission plus current-byte/template verification.
6. Make Create select only current authoring defaults while historical schemas remain display/discovery compatible.
7. Replace false-positive tests and add permanent architecture/core regression sensors.
8. Close the live canonical authority-consumer graph: rebind ordinary current permanent governing-document dependencies to the stable identifiers of the advanced concerns, reserve exact V1/V2 identifiers for intentional semantic snapshots, leave the retained historical V1 snapshots untouched, and strengthen the existing architecture sensor to reject ordinary live version pins.
9. Extend the canonical PR verification workflow with an independent current-head review gate and review submit/dismiss triggers.
10. Run complete configured verification and obtain independent R3/PR review before merge.
11. Treat only verification from the current PR candidate and current PR metadata as admissible release evidence; stale workflow attempts do not satisfy closure.

## Requirement/design traceability

Tasks 1-3 realize GW-FR-096. Tasks 3-5 realize GW-FR-097. Tasks 1 and 3 realize GW-FR-098. Task 8 (now T4) enforces the current-owner reference consequence of GW-P1-DOC-CANONICALITY across live documentation. Task 9 (T3) realizes the updated public repository delivery rule.

## Incorrect behavior to delete/replace

Delete the assumption that a WorkItem-local requirement family may silently substitute for permanent P3 authority. Replace empty-artifact promotion with exact deterministic output binding. Remove the custom 0.5.0 implementation-fidelity-audit.md from the completed historical WorkItem.

## Expected change surface

Canonical requirements/governance/contracts/architecture docs plus immutable V1 snapshots for every authority advanced to V2, pontivus-order.toml, core contracts/schema/conformance policy, stage orchestration, Create default selection, focused permanent tests, the existing PR workflow plus review-verification script, all live permanent documentation consumers of the six advanced semantic owners (including AGENTS.md and docs/README.md), changelog, and this new Defect WorkItem.

## Reproduction/regression/preservation verification

Prove empty output completion blocks; wrong/multiple/stale output fails; v2 defaults and v1 compatibility coexist; v2 stage document structure is enforced; unresolved v2 R2 `REFERENCE`/`DELTA` owners fail promotion; PLAN without exactly one valid canonical `order-tasks` block fails promotion; architecture requires the conformance/ledger/task-block enforcement seams; complete repository verification passes; independent R3/PR review remains outstanding until performed by a reviewer other than the change author. Additionally prove ordinary current governing documents use the six advanced concerns' stable identifiers rather than exact V1/V2 ids, that exact version pins remain only in intentional snapshot-bound artifacts, that all six historical V1 snapshots remain byte-identical to released 0.5.0, and that the permanent architecture sensor rejects any reintroduction of an ordinary current-document version pin. Historical 0.5.0 visual reference evidence at docs/references/workbench-ui/README.md remains explicitly exempt because its V1 basis is intentionally frozen; it must not be reclassified as governing current authority.
